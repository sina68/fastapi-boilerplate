## باگ فیکس شده

توضیح کامل در مورد باگ به وجود آمده، نشانه‌ها (Symptoms)، و لاگ‌ها یا ترِیس‌های مربوطه (مثلاً لینک به Sentry یا خطای ثبت شده در Kibana/Kube logs).

در صورتی که به ایشویی در گیت‌لب لینک است، در اینجا رفرنس داده شود (e.g. Close #12).

## چرایی به وجود آمدن/دیده نشدن باگ

- چرا این باگ به وجود آمد؟ (ریشه مشکل یا Root Cause، مثلاً عدم هندل کردن مقدار null در دیتابیس یا خطای Race Condition).
- چرا در تست‌های قبلی دیده نشد؟ (نبود تست مناسب، تفاوت محیط تست و پراد و غیره).

- **تغییرات کانفیگ / متغیرهای محیطی (.env):** آیا کلید یا متغیر جدیدی اضافه شده است؟ [بله / خیر]

## نحوه تست و بازتولید (Verification & Reproduce)

مراحل بازتولید باگ و نحوه تایید حل شدن آن در سمت بک‌اند (مثلاً با اجرای درخواست HTTP یا بررسی وضعیت دیتابیس).

> **برای مثال:**
> برای بازتولید و تست این باگ، مراحل زیر را پیش ببرید:
> 1. از ابزارهایی مثل Postman یا دستور cURL زیر استفاده کنید تا ریکوئست به اندپوینت ارسال شود:
> ```bash
> curl -X 'POST' \
>   'http://localhost:8000/sources/<id>/run' \
>   -H 'accept: application/json' \
>   -H 'Authorization: Bearer <token>'
> ```
> 2. دیتابیس را بررسی کنید که آیا وضعیت اجرا و سلامت منبع درست ثبت شده است:
> ```sql
> SELECT status, items_found, items_new, error FROM crawl_run WHERE source_id = '<id>' ORDER BY started_at DESC LIMIT 1;
> ```
> 3. اطمینان حاصل کنید که ریسپانس برگشتی خطای `500` نمی‌دهد و حاوی پیام معتبر است.

## اجرای تست‌های خودکار (Automated Tests)

تست‌های نوشته شده یا اجرا شده برای اطمینان از عدم بروز مجدد (Regression). دستور اجرای تست‌ها را بنویسید:

```bash
# مثال:
make test
# تست رگرسیون این باگ:
uv run pytest tests/<slice>/test_<module>.py -k <test_name>
```

## چک‌لیست قبل از درخواست ریویو (واجب)

- [ ] نام برنچ با پیشوند نوع شروع می‌شود (`feat/`، `fix/`، ...) و کامیت‌ها طبق Conventional Commits است.
- [ ] `make lint` و `make test` روی آخرین کامیت سبز است.
- [ ] برای هر رفتار جدید تست هست (برای روت جدید: 401 / 404 / 422، و 403 برای ادمین).
- [ ] متغیر محیطی جدید در `Settings`، `.env.example`، `tests/conftest.py` و values هلم اضافه شده.
- [ ] مایگریشن (در صورت تغییر مدل) برگشت‌پذیر است و فقط یک head داریم.
- [ ] هیچ secret، توکن یا داده شخصی در کد، لاگ، fixture یا values نیست.
- [ ] بخش مربوط از سند فاز ۱ (پیوست الف) رفرنس داده شده و هر انحراف از سند توضیح داده شده.
- [ ] `/pre-push-review` اجرا شده و موارد آن رفع شده.
