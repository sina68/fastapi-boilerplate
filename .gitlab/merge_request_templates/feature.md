## توضیح فیچر

توضیح کامل در مورد ویژگی جدید پیاده‌سازی شده، هدف کسب‌وکاری (Business Goal) و منطق فنی آن.

## تغییرات انجام شده برای پیاده‌سازی

توضیح در مورد تغییراتی که برای پیاده‌سازی این فیچر انجام شده است:
- **تغییرات API:** اضافه شدن اندپوینت‌های جدید، تغییر ساختار ورودی/خروجی (Pydantic Schemas)، تغییر وضعیت کدهای خطا.
- **تغییرات دیتابیس (Alembic):** مایگریشن‌های دیتابیس جدید، جداول جدید، ایندکس‌های اضافه شده تست شده است؟
- **تغییرات کانفیگ / متغیرهای محیطی (.env):** کلیدها یا کانفیگ‌های جدید اضافه شده.
- **سرویس‌های جانبی:** استفاده از Redis (صف/قفل/کش)، صف‌های Celery (`domestic` / `egress`)، OpenSearch (mapping یا ایندکس جدید)، پروکسی خروجی، CronJob.

## نحوه تست و سناریوهای تایید (Verification & Manual Test)

اطلاعات و گام‌های مورد نیاز برای فراخوانی اندپوینت‌ها و تست فیچر.

> **برای مثال:**
> ۱. پس از اجرای پروژه، به آدرس Swagger مستندات بروید: `http://localhost:8000/docs#/source`
> ۲. نمونه ریکوئست برای ثبت منبع جدید (`POST /sources`):
> ```json
> {
>   "type": "telegram",
>   "name": "دیجیاتو",
>   "locator": "digiato",
>   "topics": ["investment"],
>   "intervalSeconds": 900
> }
> ```
> ۳. ریسپانس مورد انتظار (`201 Created`):
> ```json
> { "id": "3f0c…", "healthStatus": "healthy", "nextRunAt": "…" }
> ```
> ۴. بررسی جدول `crawl_run` و لاگ‌ها (`source_id`، `run_id`) برای اطمینان از اجرای اولین جمع‌آوری.

## چک‌لیست قبل از درخواست ریویو (واجب)

- [ ] نام برنچ با پیشوند نوع شروع می‌شود (`feat/`، `fix/`، ...) و کامیت‌ها طبق Conventional Commits است.
- [ ] `make lint` و `make test` روی آخرین کامیت سبز است.
- [ ] برای هر رفتار جدید تست هست (برای روت جدید: 401 / 404 / 422، و 403 برای ادمین).
- [ ] متغیر محیطی جدید در `Settings`، `.env.example`، `tests/conftest.py` و values هلم اضافه شده.
- [ ] مایگریشن (در صورت تغییر مدل) برگشت‌پذیر است و فقط یک head داریم.
- [ ] هیچ secret، توکن یا داده شخصی در کد، لاگ، fixture یا values نیست.
- [ ] بخش مربوط از سند فاز ۱ (پیوست الف) رفرنس داده شده و هر انحراف از سند توضیح داده شده.
- [ ] `/pre-push-review` اجرا شده و موارد آن رفع شده.

## تاثیرات سیستمی و میکروسرویسی (System & Architecture Impact)

- **قراردادهای API و سازگاری عقب‌رو (Breaking Changes):** آیا اندپوینت‌های قبلی دچار تغییر شده‌اند؟ آیا فرانت‌اند یا اپلیکیشن موبایل با این تغییرات به مشکل برمی‌خورند؟
- **ارتباطات میکروسرویسی:** آیا تغییری در پیام‌های ارسالی/دریافتی به میکروسرویس‌های دیگر (مثلاً با gRPC یا پیام‌رسان‌ها) وجود دارد؟
- **ترتیب دپلویمنت (Deployment Order):** آیا این سرویس وابستگی به دپلویمنت سرویس دیگری دارد؟ (مثلاً اول باید سرویس X دپلوی شود تا ای‌پی‌آی جدید را داشته باشیم، یا ابتدا باید دیتابیس مایگریت شود).
- **بار و کارایی (Performance/Load):** بررسی لود دیتابیس (Query optimization)، نیاز به کش‌کردن داده‌ها، مانیتورینگ از طریق Prometheus/Grafana.
